# Backend structure

[TicketBookingDbContext](../../../src/TicketBooking.Infrastructure/Persistence/TicketBookingDbContext.cs) exposes DbSets for eleven entities and loads IEntityTypeConfiguration classes through ApplyConfigurationsFromAssembly. [Configurations](../../../src/TicketBooking.Infrastructure/Persistence/Configurations) contain explicit table names, primary/foreign keys, required columns, indexes, and money facets.

[SeatConfiguration](../../../src/TicketBooking.Infrastructure/Persistence/Configurations/SeatConfiguration.cs) defines unique auditorium/row/number coordinates with C collation on Row. [SessionSeatConfiguration](../../../src/TicketBooking.Infrastructure/Persistence/Configurations/SessionSeatConfiguration.cs) defines the session/seat unique pair. [PaymentConfiguration](../../../src/TicketBooking.Infrastructure/Persistence/Configurations/PaymentConfiguration.cs) defines booking-scoped idempotency and nonnull provider-reference uniqueness. All required FKs use Restrict deletion.

Money is an explicitly mapped EF complex value, not an owned entity: immutable instances can be shared among prices/snapshots/totals without an independent identity. [MoneyMapping](../../../src/TicketBooking.Infrastructure/Persistence/Configurations/MoneyMapping.cs) maps Amount to numeric(18,2) and Currency to required varchar(3). See [EF complex-type documentation](https://learn.microsoft.com/en-us/ef/core/modeling/complex-types).

Private constructors/setters allow materialization without invoking clocks or policy calculations. SeatHold/Booking item navigations use private List fields; public access returns read-only views. Their materialized totals/deadlines are stored values, not recalculated using current policy or catalogue prices.

Tests: [PersistenceModelTests](../../../tests/TicketBooking.IntegrationTests/PersistenceModelTests.cs) validates all entity/FK/index/money metadata without a database; [PostgresPersistenceTests](../../../tests/TicketBooking.IntegrationTests/PostgresPersistenceTests.cs) applies the migration and verifies actual round trips and PostgreSQL constraint failures. CI passes TICKETBOOKING_TEST_CONNECTION_STRING from its dedicated PostgreSQL service. These constraint tests do not implement web handlers or transactions for customer use cases. [SessionSeatConcurrencyTests](../../../tests/TicketBooking.IntegrationTests/SessionSeatConcurrencyTests.cs) now verify the version-fenced writer, tracked updates/deletes, and PostgreSQL races; see [concurrency](../session-seat-concurrency/FEATURE.md).
