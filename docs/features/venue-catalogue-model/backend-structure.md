# Backend structure

[AdminCatalogueEndpoints](../../../src/TicketBooking.Api/Administration/AdminCatalogueEndpoints.cs) registers the `/api/admin` group with AuthorizationPolicies.Admin. [Program](../../../src/TicketBooking.Api/Program.cs) maps it after authentication/authorization middleware. Handlers validate Contracts.Administration requests, coordinate the existing EF context and return response DTOs or enriched ProblemDetails. These direct framework-coordinating handlers follow the existing AuthEndpoints pattern; no separate service or CQRS layer is introduced.

CreateSessionAsync locks the auditorium, takes a shared event-row lock and loads the layout, validates future time through injected TimeProvider, derives duration and builds independent Money-backed SessionSeats. Session plus inventory use a single explicit transaction. Layout operations use the same auditorium lock. HasLayoutReferences rejects changes when either Sessions.AuditoriumId names the auditorium or SessionSeats references one of its physical Seats, even when the session header names another auditorium. RenameAuditoriumAsync uses the domain's Auditorium.Rename, preserving venue/ID; it does not change seat allocation.

UpdateSeatAsync reuses SeatRequest for all editable fields and returns SeatResponse. It resolves the seat by both IDs after locking the auditorium, checks no session exists and excludes itself when checking coordinate uniqueness. Seat.UpdateLayout validates every value before assigning fields. DeleteSeatAsync uses the same scoped lookup before the fixed-layout check. [Seat layout HTTP tests](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.SeatLayouts.cs) cover edit/readback, no-op edits, rejected edits without mutation, foreign seats, coordinate races and session races.

CreateEventRequestValidator and UpdateEventRequestValidator enforce the event input rules through asynchronous endpoint filters. UpdateEventRequest uses nullable optional fields; null means retain the stored value. After validating supplied fields and rejecting empty patches, UpdateEventAsync locks Events FOR UPDATE in an explicit transaction, merges against the latest values and calls Event.UpdateDetails. The domain validates every value before mutation. Scheduling holds FOR SHARE on the event through commit, coordinating status/duration reads with updates while retaining existing captured session times. [Event HTTP tests](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.Events.cs) cover creation, partial edits, field errors, publishing/archiving, historical sessions and concurrent edits/scheduling.

UpdateSessionAsync validates the partial UpdateSessionRequest, locks Sessions FOR NO KEY UPDATE, locks source/target auditoriums in sorted order, shares the event lock and locks inventory rows in ID order. It rejects nonfuture/non-Scheduled sessions, any hold/booking history, non-Available or incomplete source inventory and missing/empty target layouts. Start-only edits retain captured duration; event changes derive duration from the new published event. Domain Session.UpdateSchedule validates parent IDs and end-after-start before mutation. Starts are normalized/rechecked after locking. Moves require a uniform stored price and use tracked version-checked inventory deletes plus fresh inserts. Other edits mark inventory Version modified so the existing DbContext advances its fencing tokens. All changes commit together. GetSessionAsync uses a RepeatableRead transaction to return a coherent snapshot during moves. [Session HTTP tests](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.Sessions.cs) cover updates, moves, validation, history, stale allocations, rollback and racing allocation.

The [request/response contracts](../../../src/TicketBooking.Contracts/Administration) contain no Domain/EF dependencies. Enum values are integer fields validated against Domain enums at the API boundary. IDs, end time and initial inventory state are server-controlled. All required fields/limits are listed in the [HTTP contract](admin-http-contract.md).

The existing [configurations and migration chain](../local-persistence/FEATURE.md) supply the schema. No new tables/columns or migrations are needed. Initial inventory inserts use version zero; existing SessionSeat ownership writes still require the [concurrency writer](../session-seat-concurrency/FEATURE.md).

[Admin HTTP tests](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.Administration.cs) cover all 18 routes' 401/403 enforcement, complete creation/readback, name changes, unused-layout removal, immutable used layouts, validation/conflicts, parent existence, duplicate-batch races and layout/session races. A SavedChanges interceptor forces failure after session/inventory writes to verify rollback and retry. [VenueTests](../../../tests/TicketBooking.Domain.Tests/VenueTests.cs) additionally test rename identity preservation and unchanged state on invalid names. Session cancellation, schedule-overlap enforcement and customer allocation workflows remain absent.

[Inventory-generation HTTP tests](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.SessionInventory.cs) exercise zero, one cent and Money.MaxAmount in UAH/EUR/USD, normalized currency, generated IDs, full physical-seat coverage and independent persisted Money values across sibling seats and sessions. Tracked repricing of one generated seat is reloaded to verify isolation. The Admin tests also reject missing/blank/overflow prices and ignore forged submitted inventory; rollback/concurrent layout tests cover atomic creation. The generation behavior already existed before these additional regressions.

HasReservationReferences checks both SeatHolds/Bookings.SessionId and SeatHoldItems/BookingItems.SessionSeatId after inventory is locked. It uses no history-status filter: Active/Expired/Converted/Cancelled holds and PendingPayment/Confirmed/Cancelled/Expired/Refunded bookings all prevent edits, even with Available inventory. [Edit-protection HTTP tests](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.EditProtection.cs) exercise every history status, compare persisted state after rejected add/edit/delete/move/event/start changes, construct inconsistent header/item/physical-seat fixtures and race full hold/booking commit transactions against session edits. These guards are API management checks; raw database writers still need the allocation transaction contract.

[CatalogueEndpoints.MapCatalogueEndpoints](../../../src/TicketBooking.Api/Catalogue/CatalogueEndpoints.cs) registers anonymous GET /api/events in Program. GetEventsAsync validates query/date/venueId/page/pageSize before database execution. It filters Published events with parameterized escaped ILIKE on title/description. Date/venue constraints share one correlated Scheduled-session query joined through Auditorium.VenueId, avoiding duplicate events and cross-session matches. It counts and selects a deterministic title/ID page inside a RepeatableRead transaction, with SQL Skip/Take and no entity/seat materialization. [Contracts.Catalogue](../../../src/TicketBooking.Contracts/Catalogue) owns EventSummaryResponse and EventListResponse. [Public event HTTP tests](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.PublicEvents.cs) cover filtering, visibility, date boundaries, pagination and validation. No schema change or new configuration is required.

Public GetEventAsync projects Published event details to EventSummaryResponse. GetEventSessionsAsync binds CatalogueQuery and invokes CatalogueQueryValidator for date/venueId/page/pageSize before parsing, checks Published parent existence, and counts/pages Scheduled sessions inside RepeatableRead. PublicSessions centralizes event/session visibility; ProjectSessions joins auditorium and venue metadata, ordering by StartsAt then ID before bounded paging. GetSessionAsync returns that metadata in one database query. GetSessionSeatsAsync sets Cache-Control: no-store and reads session/inventory/layout within RepeatableRead. It projects only the requested inventory, orders physical coordinates, verifies count/auditorium consistency and returns either the complete map or 409. Stored availability and Version are returned unchanged; no expiry inference, hold lookup or owner fields are added. [Public detail HTTP tests](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.PublicDetails.cs) cover the four routes, hidden parents/states, metadata, map privacy/refresh, filtering/pagination, inconsistent inventory and a concurrent auditorium move.

All five public handlers now return typed Results unions with Ok<their concrete Contracts DTO>, NotFound and/or ProblemHttpResult as appropriate; they no longer expose an unrestricted IResult success boundary. Invalid still enriches the existing validation ProblemDetails. EventListResponse and EventSessionListResponse share [PagedResponse<T>](../../../src/TicketBooking.Contracts/PagedResponse.cs), preserving the original four fields and adding computed navigation metadata. The shared contract validates positive page/pageSize and nonnegative counts; endpoint input bounds remain unchanged. [Pagination contract tests](../../../tests/TicketBooking.IntegrationTests/PaginationContractTests.cs) cover empty/last/out-of-range/Int32-limit metadata and JSON round-tripping. [Public response HTTP tests](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.ResponseContracts.cs) assert exact success field sets, concrete success metadata types and live navigation values for both list routes.

[CatalogueValidation](../../../src/TicketBooking.Api/Validation/CatalogueValidation.cs) explicitly registers the FluentValidation 12.2 validators. ValidateRequest<T> is an async Minimal API endpoint filter on every Admin body write, executing after authorization and before handler side effects. Public list handlers bind raw query values, invoke CatalogueQueryValidator.ValidateAsync, then parse only validated input. RequestRules reads injected TimeProvider at validation time and reuses Money validation. No MVC auto-validation or deprecated ASP.NET integration package is used. Post-lock time checks and all storage-dependent conflicts remain transactional handler responsibilities.

[ApiProblemDetails.Validation](../../../src/TicketBooking.Api/Errors/ApiProblemDetails.cs) groups FluentValidation failures under existing camelCase/indexed field names and retains validation_failed/type/instance/traceId. Program uses [AddDocumentedOpenApi](../../../src/TicketBooking.Api/Errors/DocumentedOpenApi.cs); [ProblemDetailsOperationTransformer](../../../src/TicketBooking.Api/Errors/ProblemDetailsOperationTransformer.cs) adds descriptions and safe examples to declared catalogue/admin ProblemDetails responses. The real Program still maps OpenAPI only in Development; the test fixture explicitly maps it for generated-document assertions. See [validation and response documentation](validation-and-problems.md).

[DevelopmentSampleDataCommand](../../../src/TicketBooking.Api/Development/DevelopmentSampleDataCommand.cs) implements --seed-sample-data before normal API/auth initialization. Development/connection checks precede host/persistence resolution. It builds a scoped host without starting HTTP, registers TimeProvider and [DevelopmentSampleDataSeeder](../../../src/TicketBooking.Api/Development/DevelopmentSampleDataSeeder.cs), then prints safe IDs/start time and exits. Seeder repeats the environment guard, uses a transaction-scoped PostgreSQL advisory lock to serialize empty-database/rerun races, creates only missing fixed-ID roots, then takes auditorium FOR UPDATE/event FOR SHARE locks. Empty unused layouts receive 24 seats; nonempty layouts are reused, while empty used layouts are refused. Existing future sessions must have complete matching inventory and are returned unchanged. Otherwise a fresh future session/inventory is inserted. A failed save rolls back the entire graph. No migration application, admin creation or automatic startup seeding occurs in the command. [Seed tests](../../../tests/TicketBooking.IntegrationTests/DevelopmentSampleDataTests.cs) cover these paths and a real one-shot CLI invocation.

[Additional PostgreSQL catalogue regressions](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.CatalogueRegression.cs) combine filters with bounded pages and distinct totals, collect simultaneous query errors with an unsupported Accept header, reuse the shared 18-route AdministrationRequests matrix for roleless/tampered/expired credentials, compare guest/Customer seat maps to stored price limits, and assert no inventory/history mutation at a persisted hold expiry. Existing PostgreSQL suites retain anonymous/Customer denials, exact DTO fields, all availability states, hidden/inconsistent maps, validation limits and concurrency cases. See [testing coverage](testing.md).

## Seat-availability projection cache

GetSessionSeatsAsync reads compact inventory ID/version rows before Redis only when the physical layout meets the configured threshold. [RedisSeatAvailabilityCache](../../../src/TicketBooking.Infrastructure/Caching/RedisSeatAvailabilityCache.cs) implements [ISeatAvailabilityCache](../../../src/TicketBooking.Application/Catalogue/ISeatAvailabilityCache.cs); [SeatAvailabilityRevision](../../../src/TicketBooking.Infrastructure/Caching/SeatAvailabilityRevision.cs) hashes ordered ID/version pairs. Keys also include session/auditorium IDs. Hits skip the map join; misses retain its consistency checks and fill only after read commit. Program registers bounded SeatAvailabilityCache options and the adapter using the existing Redis provider. See [invalidation and tests](seat-availability-caching.md).
