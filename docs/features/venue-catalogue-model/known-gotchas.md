# Known gotchas

- **Observed:** Publishing is explicit: CreateEventRequest defaults Status to Draft (0); use Published (1) for session creation. PATCH can publish, archive or return to Draft; all defined transitions are allowed. Omitted/null fields retain stored values, while empty description clears it. An all-null/empty patch is rejected.
- **Observed:** Any session, including cancelled/completed ones, freezes its auditorium's physical layout and blocks auditorium deletion. Rename remains allowed. Seat edits return 409 once used; before scheduling, PATCH can change row/number/type without replacing the seat ID. PATCH supplies the complete editable fields; omitted type defaults to Standard (0). This conservative rule preserves inventory history; no layout versioning or existing-session backfill is provided.
- **Observed:** Session creation applies one validated price/currency to every physical seat. Per-type pricing, discounts, repricing and manual unavailability controls are absent. Client-supplied end/status/inventory fields are ignored.
- **Observed:** Event duration/status edits do not alter existing session times, cancellation status or inventory. Archive blocks new scheduling, not existing sessions. Event updates and scheduling hold exclusive/shared event-row locks respectively; concurrent edits to the same field apply in lock order without stale-client detection.
- **Observed:** Session PATCH edits only eventId/auditoriumId/startsAt on future Scheduled sessions without hold/booking history and with all inventory Available. Archived events block updates; republish first. Start-only edits retain captured duration. Auditorium moves rebuild inventory with new IDs and require a uniform stored price; refresh the returned map. Other edits (including no-op requests) increment inventory versions. No cancellation, status mutation, repricing or captured-deadline migration is provided.
- **Observed:** Session-history guards include both aggregate headers and inventory-item links, and layout guards include physical-seat inventory links. Inconsistent stored relationships cause 409 rather than permitting further invalidation. They require separate data repair; no automatic rewrite is performed. Historical cancelled/expired/refunded records still block session edits even when inventory is Available.
- **Observed:** Inventory fencing relies on customer workflows using version-checked allocation writes and committing hold/booking history in the same transaction. Direct SQL/history inserts outside that contract remain outside management race protection.
- **Observed:** POST creates have no request idempotency key. A lost success response can lead to duplicates if blindly retried; use returned Location/IDs. Seat coordinates are case-sensitive and trimmed by HTTP input; duplicate batches are atomic conflicts.
- **Observed:** No schedule-overlap or cleaning-buffer rule exists. Multiple sessions can overlap within an auditorium. Future scheduling changes require an explicit policy rather than assuming the current row lock prevents overlap.
- **Observed:** Admin layout/session writes serialize through the auditorium row lock. Direct SQL/EF callers that bypass it can violate application-only layout consistency; keep future management operations on the same locking path. Existing foreign keys/unique keys still apply.
- **Observed:** Names/title/address/row/description bounds apply at HTTP validation only; existing text columns are unchanged. New sessions normalize instants to UTC/PostgreSQL microseconds before response; domain constructors elsewhere retain their existing precision behavior.
- **Observed:** SessionSeat.Version starts at zero for inventory creation. Setup never authorizes ownership transitions; use the allocation writer for later changes.
- **Not verified:** Browser TLS trust, frontend UX, deployed database migration state, public browsing UI and external provider behavior. Tests use disposable PostgreSQL; no development data is changed.

- **Observed:** Public event listing uses UTC session-start dates, not venue-local days or session overlap with a day. Date and venue must match one Scheduled session. No automatic future-only or seat-availability filter is applied; Published unscheduled events appear when neither date nor venue is supplied.
- **Observed:** Public search is a literal case-insensitive substring on title/description; LIKE wildcards are escaped. No relevance ranking, accent normalization or full-text index is introduced. Title/ID ordering is deterministic within the response snapshot; separate page requests can shift under concurrent catalogue changes.
- **Observed:** pageSize is rejected outside 1–100, rather than clamped. Blank numeric/date/venue parameters and duplicate parameter values are 400. Unknown valid venue IDs return empty results.

- **Observed:** Public session lists/details/maps hide Cancelled/Completed sessions and sessions of Draft/Archived events as 404/omitted results. Scheduled sessions are not automatically hidden by the clock, consistent with listing’s explicit date policy.
- **Observed:** Seat maps show persisted availability, including Held seats whose expiration worker has not released them. no-store and Version help clients refresh; neither a map nor its token reserves a seat or proves ownership.
- **Observed:** Incomplete or cross-auditorium inventory produces 409 without partial or foreign seat data. These routes do not repair inconsistent records. An empty auditorium with empty inventory can return an empty map; normal Admin creation requires a nonempty layout.

- **Observed:** Navigation flags reflect the requested page index and filtered count, not whether that page contains items: HasPreviousPage is true for any page > 1, including empty/out-of-range pages; HasNextPage is false once page >= totalPages. Empty datasets have totalPages=0. Existing top-level fields and detail/map DTO shapes are retained.

- **Observed:** FluentValidation errors use the established field-key format, including seats[index].field and query parameter names. Duplicate parameters are rejected rather than merged. Null patch fields remain omitted values; all-null patches remain invalid.
- **Observed:** FluentValidation checks input, not current storage state. Duplicate coordinates, missing parents, existing reservations and deadlines after lock waits remain handler checks. FV rules are not automatically converted into JSON-schema length/range constraints; limits are documented in the HTTP contract.
- **Observed:** Generated 400 examples illustrate field validation. Malformed JSON, null required bodies and type binding failures can return ProblemDetails without errors. Unsupported body content types are 415 http_error. OpenAPI remains Development-only in the actual application.

- **Observed:** --seed-sample-data requires Development and already-applied migrations; it does not start HTTP or apply schema changes. Run it separately from --initialize-admin.
- **Observed:** Reserved root IDs, not names, identify sample data. An unrelated venue with the same display name is untouched. Modified sample names/prices/allocated seats remain unchanged; an archived movie, changed auditorium parent or incomplete future inventory causes failure instead of automatic repair/reset.
- **Observed:** When no future Scheduled sample session remains, rerunning adds a new one. Older sessions retain stored status/times and can still appear under the catalogue’s explicit date policy. No expiry worker, cancellation, release or refund is triggered.

- **Inferred-risk:** Low hit rates can make revision-query, hashing and Redis costs exceed the saved projection work. Default eligibility is 64 seats with five-second TTL; disable/tune SeatAvailabilityCache using actual measurements. No production performance benchmark has been run.
- **Observed contract:** Direct SQL that bypasses inventory Version advancement or immutable-layout rules also bypasses revision invalidation. Use the fenced writer or tracked-save protocol; never use cached availability as a reservation. Old revision keys can coexist briefly until TTL. Full booking confirmation/release workflows remain separate work; see [the implemented primitive contract](seat-availability-caching.md).
