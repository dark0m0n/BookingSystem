# Known gotchas

- **Observed:** IdentityCore alone only registers storage. Program now adds SignInManager, JWT authentication/authorization and real auth routes. No booking endpoints are added, so business handlers must still wire the reusable ownership checks.
- **Observed:** Password/normalization validation is bypassed by direct EF inserts. Use managers for accounts and safe DTOs for responses. Registration's unique-index catch handles only known account constraints, not arbitrary SQL failures.
- **Observed:** Existing duplicate normalized emails prevent the new unique index from being applied. The migration preserves accounts and does not resolve those conflicts automatically. Legacy rows receive an empty display name.
- **Observed:** Registration reports a duplicate account; login uses identical generic failure text for unknown/wrong/locked/unsupported-two-factor cases. Equal timing or resistance to account enumeration is not guaranteed. Identity lockout is enabled; no IP rate limiter is added.
- **Observed:** A two-factor-enabled account cannot use this password-only endpoint. MFA completion and confirmed-email flows are deferred; email confirmation is not required by current defaults.
- **Observed:** Access tokens remain valid until expiry even after password/role changes or account deletion; middleware validates cryptography/lifetime, not a live security stamp. Refresh-family revocation now blocks renewal after replay/account ineligibility; it does not revoke access JWTs. Public family logout is implemented; immediate access-token revocation and key rotation workflows remain absent. Roles are snapshots at each login/refresh.
- **Observed:** Signing keys require ≥32 random UTF-8 bytes; issuer/audience must be nonblank and lifetime 1–1440 minutes. Invalid settings fail startup, including EF design-time commands. Use long dummy keys for design-only commands and User Secrets for actual local startup. Never return/log the key.
- **Observed:** Role definitions are seeded by migration; public registration assigns only Customer. Admin is never granted from client role/isAdmin/permissions fields. Only stored memberships enter JWTs. Customer/Admin fixture routes exist only in tests; production business endpoints must explicitly apply the named policies.
- **Observed:** Business UserId FKs/backfill and account deletion coordination remain absent. Identity dependents cascade; business references restrict deletion.
- **Observed:** JWT issuance/validation use injected TimeProvider with no expiry grace; Identity manages its own framework password/lockout behavior. Request passwords are not trimmed and are limited to 128 characters by these endpoints.

Tests migrate isolated PostgreSQL schemas and skip without TICKETBOOKING_TEST_CONNECTION_STRING. They verify HTTP/auth/storage behavior with production extensions, not complete Program startup, TLS, external email, public business authorization, MFA completion or immediate access-token revocation. The development database was not modified.

- **Observed:** Strict replay detection revokes the family even for benign concurrent refresh requests or a retried request whose first response was lost. Serialize refreshes across callers/tabs; sign in again after invalid_refresh_token or ambiguous completion. There is no replay grace or way to recover the discarded plaintext replacement from its hash.
- **Observed:** A successful rotation commits before its JSON response. Database failure before commit rolls back consumption; response delivery failure after commit does not. No transparent retry can distinguish those outcomes safely.
- **Observed:** RefreshTokens are not cookies and no browser storage strategy is prescribed. Keep raw tokens out of logs/URLs and send them only in the HTTPS JSON contract; hashes are for storage, not client credentials.
- **Observed:** Family expiry never slides; default seven days is configurable for new logins through Jwt:RefreshTokenDays (1–90). Existing families retain their captured deadlines. Issued access JWTs retain their independent expiry and can outlive refresh eligibility.
- **Observed:** There is no cleanup worker or public session-list/all-device management route; logout revokes only the presented token's family. Keep consumed-token history for live families; arbitrary deletion removes replay detection. User deletion cascades that user's refresh rows.

- **Observed:** Logout accepts any retained generation, so a consumed ancestor can revoke current descendants. Repeated/unknown well-formed logout gets 204; malformed input gets 400. This is a refresh-credential capability, not an endpoint accepting arbitrary user/family IDs. The client must discard its access JWT too; server-side access validation still allows it until exp.
- **Resolved test issue:** Isolated-schema fixtures own/dispose their NpgsqlDataSource pools. Do not leak an independent idle pool per schema or increase PostgreSQL max_connections to hide the leak.

- **Observed:** Apply the role data migration before using public registration. A missing Customer definition or membership-write failure returns a safe error and rolls back account creation; the endpoint does not create fallback roles. Existing roleless users remain roleless until a trusted assignment/backfill decision. No default admin account is created.
- **Observed:** Role names in JWTs are case-sensitive; the seed migration canonicalizes matching normalized definitions. Admin changes are reflected by new login/refresh tokens; an old access JWT keeps its prior claims until expiry. Downgrading the role migration intentionally retains role definitions/memberships.

- **Observed:** `--initialize-admin` requires Development and already-applied migrations; normal startup does not initialize an account. It exits without HTTP/JWT setup. Missing role data fails rather than inserting fallback definitions.
- **Observed:** Rerunning the initializer with another password does not reset an existing admin. Existing non-admin email/username conflicts are refused; use a distinct admin email. Supply credentials through the [interactive prompt or external configuration](development-admin.md), never command-line literals or tracked files.

- **Observed:** Customer role eligibility alone does not grant resource access, including for Admin. Invoke ResourceOwnershipService for loaded resources before data return or side effects; production business routes are not implemented yet.
- **Observed:** Passing a caller-owned booking with another payment is rejected even if both bookings belong to the same owner. Always resolve the actual persisted parent. Raw EnsureOwner expects a server-resolved owner; request IDs cannot establish ownership.
- **Observed:** Missing/malformed/duplicate sub or multiple authenticated identities produce no current caller. Ownership service returns 401 instead of comparing empty IDs. Refunds have no entity-specific adapter yet; see [planned traversal](resource-ownership.md).

- **Verification prerequisite:** Database-backed auth tests skip without TICKETBOOKING_TEST_CONNECTION_STRING; use a disposable database and confirm zero skipped cases. See [the test matrix](testing.md). TLS/browser trust and production business endpoint wiring are outside these fixtures.
