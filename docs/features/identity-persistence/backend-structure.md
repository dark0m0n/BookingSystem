# Backend structure

- [AuthEndpoints](../../../src/TicketBooking.Api/Auth/AuthEndpoints.cs) maps the four anonymous POST routes, validates bounded request fields and coordinates Identity. Registration recognizes DuplicateEmail/DuplicateUserName and only PostgreSQL UniqueViolation on EmailIndex/UserNameIndex; other provider failures propagate to safe generic errors.
- [AuthenticationConfiguration](../../../src/TicketBooking.Api/Auth/AuthenticationConfiguration.cs) registers JWT bearer/authorization and a scoped JwtTokenIssuer. [JwtOptions](../../../src/TicketBooking.Api/Auth/JwtOptions.cs) validates issuer/audience, signing key ≥32 UTF-8 bytes, access lifetime 1–1440 minutes and refresh-family lifetime 1–90 days during registration. Configuration is captured at startup.
- [JwtTokenIssuer](../../../src/TicketBooking.Api/Auth/JwtTokenIssuer.cs) emits HS256 JWTs with independent jti, GUID sub, stored email and roles. Numeric dates/response expiry share whole-second UTC precision. TimeProvider drives issuance and the lifetime validator; signature/issuer/audience validation remains framework-owned.
- [Program](../../../src/TicketBooking.Api/Program.cs) adds SignInManager to the existing Identity registration, invokes authentication registration and uses authentication/authorization middleware after HTTPS redirection.
- [ApplicationUserConfiguration](../../../src/TicketBooking.Infrastructure/Persistence/Configurations/ApplicationUserConfiguration.cs) adds required varchar(200) DisplayName and unique normalized EmailIndex after base Identity model configuration. Existing business version logic remains intact.

[AuthEndpointsTests](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.cs) uses production route/service extensions, real HTTP, PostgreSQL and a controllable clock; synthetic protected/Admin routes verify JWT/principal/role behavior. Those test routes are not registered in Program. [AuthenticationConfigurationTests](../../../tests/TicketBooking.IntegrationTests/AuthenticationConfigurationTests.cs) covers invalid startup settings without a database. Existing Identity storage/concurrency tests remain relevant.

Identity's default password and lockout policies are retained. No default token providers, email sender, cookie sign-in, default admin account, session-list/all-device administration or MFA completion is added. Authentication services do not change existing business ownership checks or introduce allocation transactions.

[JwtBearerValidationTests](../../../tests/TicketBooking.IntegrationTests/JwtBearerValidationTests.cs) adds database-free HTTP coverage for production issuer/bearer integration, exact audience matching, required claims/signatures, tampering, pinned algorithms and one-tick not-before/expiration boundaries. It does not register a production route or replace the existing PostgreSQL account tests. See [validation parameters and response semantics](jwt-validation.md).

[RefreshTokenService](../../../src/TicketBooking.Infrastructure/Identity/RefreshTokenService.cs) lives in Infrastructure and is registered with the immutable RefreshTokenPolicy by AuthenticationConfiguration. It uses the shared context and Identity account policy; it never signs JWTs. Raw secrets exist only in a returned grant/request/response, while the database stores hashes. JwtTokenIssuer now returns an IssuedAccessToken; the endpoint combines it with the committed refresh grant into LoginResponse.

[AuthEndpointsTests.Refresh.cs](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.Refresh.cs) extends the real HTTP/PostgreSQL fixture. It covers security/expiry/races, reloading through an independent provider, current account roles/profile and a SaveChanges interceptor that forces replacement failure after consumption to verify rollback. No token cleanup or background worker exists.

Logout calls RefreshTokenService.RevokeAsync with the submitted secret. RevokeAsync and RotateAsync both use LockSessionAsync and RevokeFamilyAsync; revocation updates only an unset RevokedAt, preserving idempotency and the first timestamp. Unknown hashes do not disclose family state. The existing schema already stores revocation/history, so this step adds no migration.

[AuthEndpointsTests.Logout.cs](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.Logout.cs) covers ancestor logout, family isolation, expiry/unknown/revoked cases, duplicate logouts, rotation races and rollback before commit. Isolated HTTP/Identity/seat-concurrency fixtures now own and dispose NpgsqlDataSource pools; per-schema idle pools previously exhausted the test server's connection limit. The independent-provider refresh test uses the original fixture configuration because data sources redact passwords in exposed connection strings.

RoleNames lives in Domain.Identity without framework dependencies. AuthorizationPolicies and AuthenticationConfiguration register named policies in the API: Customer requires authentication and Customer-or-Admin; Admin requires authentication and Admin. AuthEndpoints.RegisterAsync shares the scoped context with UserManager and encloses creation/Customer assignment in one transaction. No public endpoint accepts a role to assign.

[SeedCustomerAndAdminRoles](../../../src/TicketBooking.Infrastructure/Persistence/Migrations/20261105211207_SeedCustomerAndAdminRoles.cs) upserts normalized roles, canonicalizes their names and retains existing IDs/memberships. Down deliberately retains role data. [Role HTTP tests](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.Roles.cs) exercise the named policies with actual login/refresh tokens, legacy role migration and forced membership-write rollback. [AuthorizationPolicyTests](../../../tests/TicketBooking.IntegrationTests/AuthorizationPolicyTests.cs) covers role/authentication combinations without PostgreSQL.

[DevelopmentAdminCommand](../../../src/TicketBooking.Api/Auth/DevelopmentAdminCommand.cs) is an explicit one-shot Program branch, guarded by IsDevelopment before persistence registration. It reads DevelopmentAdmin:Email/Password/DisplayName externally, uses the existing Identity stores and one transaction, and exits without starting HTTP or configuring JWTs. Normal startup never calls it. [Command tests](../../../tests/TicketBooking.IntegrationTests/DevelopmentAdminCommandTests.cs) and [PostgreSQL tests](../../../tests/TicketBooking.IntegrationTests/DevelopmentAdminPersistenceTests.cs) verify guards, actual CLI exit, hashing, idempotency, conflicts and rollback. No new migration is needed.

[HttpCurrentUser](../../../src/TicketBooking.Api/Auth/HttpCurrentUser.cs) implements Application's ICurrentUser using a single authenticated GUID sub. AddTicketBookingAuthentication registers IHttpContextAccessor and scoped ICurrentUser/ResourceOwnershipService. The service checks loaded holds/bookings and a payment's matching parent booking; Domain.Identity.ResourceOwnership supplies the common equality rule now used by hold/booking transitions too. ApiErrorCatalog maps AuthenticationRequiredException to 401; ResourceNotOwned remains 403. No business route, database reader or refund entity is added; see [ownership usage and tests](resource-ownership.md).

[AuthEndpointsTests.Security.cs](../../../tests/TicketBooking.IntegrationTests/AuthEndpointsTests.Security.cs) adds failed-login refresh-storage assertions and cross-user identity/family isolation. Role tests also prove prior Admin access claims persist only until expiry after membership removal. See the [scenario matrix and run commands](testing.md). No application behavior or schema is changed by this test expansion.
